## 3. 四个机关的交互逻辑与实现

### 3.1 红毯过坑 —— 不是机关，是一条"防逃课规则"

| 项 | 内容 |
|---|---|
| 触发 | 玩家按 Q |
| 允许条件 | `SafetyFootRing.CanSwitch` |
| 判定 | 脚下**站得住**（`standMask`：Shared_Both + 2D 红毯 + 3D 枯木桥）**且** 沿 X 轴扫到一段宽 ≥ 0.75 m、上方有 1.7 m 净空的 `Shared_Both` 平台 |
| 结果 | 允许 → 切维度并把人 **X 吸附**到平台中心；不允许 → 光圈暗红 + 0.45 s 红闪 |
| 数字 | 扫描步长 0.25 m，半宽 10 m，同平面容差 0.45 m |
| 为什么这么做 | 如果只查"脚下有东西"，玩家能在 2D 红毯上切回 3D 直接掉进深渊；如果只查"有 3D 地面"，玩家站在红毯上连 Q 都按不动（这就是我修的那个 bug） |

### 3.2 十年树木

| 项 | 内容 |
|---|---|
| 玩家动作 | 2D 走到花洒旁按 **E** |
| 第 1 步（花洒） | `WaterSprinkler.Push()`：检查 `activeIn==Past2D` 且没推过 → 沿 +Z 以 2 m/s 滑向 `targetZ=17.5`，同时画一条 LineRenderer 水流 |
| 第 2 步（浇水） | 到达 → `tree.Water()` |
| 第 3 步（因果） | `Water()` 里一次做三件事：<br>① `glassCollider.enabled=false`（路立刻通）<br>② 0.15 s 后隐藏玻璃网格（让玩家看见"碎"的过程）<br>③ 触发 `onGrown`，**切回 3D 时**枯木桥从 0 长到 1（`growDuration=1.0 s`） |
| 关键判定 | `DimensionRules.ActiveIn(waterIn)` —— 只有 2D 能浇水；`bridge==null || 只有 3D 时才生长` |
| 数字 | 桥 3.2×0.8×7.0，走人门槛 `walkableAt=0.35`（长到 35% 就能踩） |
| 玩家看到的因果 | 「水在 2D 浇下去 → 玻璃碎了 → 3D 里长出一座桥」——三个后果同一个动作，不拆成三个开关 |

### 3.3 双墙齿轮（本关的"侧视王牌"）

| 项 | 内容 |
|---|---|
| 玩家动作 | 3D 拉 Z=27 的拉杆（E）→ 主动轮开始转 → Q 切 2D |
| 判定公式 | `间隙误差 = |轮心距 - (r1 + r2)|`<br>`轮心距 = 2D ? 投影(Y,Z)距离 : 真实三维距离`<br>`咬合 = 主动轮在转 && 间隙误差 <= toothGap(0.15)` |
| 3D 实测 | 投影距 3.30（看着"对齐"），但真实距离 **19 m** → 间隙误差 16.0 → **不咬** |
| 2D 实测 | 投影距 3.30 = 1.65+1.65 → 间隙误差 **0.000** → 咬合，从动轮转速 = -主动轮 × (r1/r2) |
| 完成条件 | `drivenGear` 累计转够 `requiredTurns=1` 圈（360°）→ `onCompleted` → 大门 `ForceOpen()` |
| 数字 | 主动 60°/s，从动 -60°/s，转一圈 6 s（实测 468° 时门开，多出来的是转场期间继续转的） |
| 为什么不用 bool | 策划把墙间距从 19 m 改成 22 m，咬合行为自动跟着变；写 `canMesh = is2D` 就废了 |

### 3.4 错位断桥 + X 轴吸附

| 项 | 内容 |
|---|---|
| 环境 | 3D：左桥 Z∈[36,42] X=-5；右桥 Z∈[41,47] X=+5（错开 5 m）；2D：一整条 Z∈[36.25,46.75] 的桥 |
| 玩家动作 | 站左桥按 Q → 沿 Z 走到 44 → 按 Q |
| 判定 | 2D 时 X 锁在 -5；切回 3D 时 `safetyFootRing` 沿 X 扫：
- X=-5 处（Z=44）**没有 3D 地面**（左桥只到 Z=42）
- 继续往 +X 扫，在 X=+5 扫到右桥（Z 41~47 覆盖 44）
| 结果 | 把玩家瞬间吸附到 (X=+5, 桥面) —— 实测 `x=-5.00 → +5.00` |
| 为什么这是"王牌" | 玩家在 2D 里根本没动 X，切回来却换了条道；这是全作唯一一个"侧视里看不出、切回来才发生"的空间操作 |

## 4. 要提醒同事的 10 件事

| # | 提醒 | 为什么 |
|---|---|---|
| 1 | **`ProjectSettings/TagManager.asset` 必须提交** | 4 个维度 Layer 的**序号**被预制体和场景引用；别人拉下来序号不同，所有物件掉回 Default 层，2D 里该消失的东西全部穿帮 |
| 2 | **不要改 `Assets/Scenes/Hall01.unity` 里的对象层级**，改了就重跑菜单 6 | 生成器是"整场景重建"，手改的东西会被覆盖；要长期改请在 `HallOneBuilder.cs` 里改 |
| 3 | **2D 里 X 是锁死的** | 玩家只能在自己切换那一瞬间的 X 上活动。**同一条 2D 走廊上的机关，X 必须一致**，否则玩家永远够不着（第一展厅全线 X=0，断桥例外，靠吸附） |
| 4 | **`standMask` 和 `groundMask` 别混** | `groundMask` 只放 Shared_Both（3D 落点）；`standMask` 是"站得住"（含 2D 红毯、3D 枯木桥）。混用的后果我踩过：整关卡死 |
| 5 | **`UnityEvent` 字段必须 `= new UnityEvent()`** | 别的脚本 `AddComponent` 后立刻 `AddPersistentListener` 会 NRE，而且只在编辑器构建时报，运行时看不出来 |
| 6 | **机关判定用几何，不要用 `bool = is2D`** | 详见 `INTERFACES.md` §8；bool 在策划改坐标那天就废了 |
| 7 | **白膜阶段掉进深渊没有重生** | 掉下去只能重开 Play。正式版要加 kill volume + 回检查点 |
| 8 | **门外那块 9 m 过渡平台是我加的** | 文档没写 6 m 门洞到 X=-5 左桥之间那 2 m；不加会掉虚空。**需要策划拍一下** |
| 9 | **巡卫/碎片/电梯是占位方块** | 接战斗和收集系统时**不要删** `GrowthTree` / `GearPair` / `WaterSprinkler`，它们是真正跑通的逻辑 |
| 10 | **齿轮半径 1.65 是从 3.3 m 投影距反推的** | 改任何一边的 Z，都必须重算半径，否则"看着咬合其实穿模" |
