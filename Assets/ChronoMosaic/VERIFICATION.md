## 跑出来的三个真 bug（都已修）

### 1. 光圈在 Awake 之前被调用 → NullReferenceException

`SafetyFootRing.Paint()` 用了一个在 `Awake()` 里才创建的材料属性块。
只要别的脚本在自己的 `Awake()` 里调 `RefreshNow()`，或者编辑器里手动触发，就直接炸。

修法：`Paint()` 里懒创建。

### 2. 落点探测把玩家自己当成了障碍物 → 永远不能切

`HasHeadroom()` 用 `Physics.CheckCapsule(` 检测头顶净空，遮挡层是"全部"，
而玩家的 `CharacterController` 正好在这个胶囊里 —— 每一段地面都被判成"头顶有东西"，
于是 `CanSwitch` **恒为 false**，2D→3D 永远被拒绝。

这个 bug 在编辑器里看不出来（编辑器物理查询返回空，测试会"碰巧"跳过），
只有真跑起来才会暴露成"按 Q 没反应"。修法：用 `OverlapCapsuleNonAlloc` 并跳过 probe 自己的子物体。

### 3. 探测层包含了 2D 专属地面 → 站在红毯上会掉进深渊

原来的 `groundMask = Shared_Both + Past2D_Only`。红毯桥在 2D 是实心的，
于是站在红毯上时探测"发现脚下有地面"，允许切回 3D —— 但 3D 那边是深渊，玩家直接掉下去。

修法：`groundMask` 只认 `Shared_Both`（两个维度都实心的承重地面）。
规则落到关卡上就是一句话：**所有承重地面放 Shared_Both，装饰性构件放各自维度层。**

### 重写的关键：判定来自几何，不来自开关

齿轮的啮合不再是 `bool = is2D`，而是**两轮外切**：

`@csharp
间隙误差 = |轮心距 - (r1 + r2)|
轮心距   = 2D ? 投影(Y,Z)距离 : 真实三维距离
咬合     = 主动轮在转 && 间隙误差 <= 齿隙
`@

于是"隔 19 m 咬不上、投影相切能咬上"是算出来的。
实测 3D 间隙误差 16.0、2D 0.000 —— 策划把齿轮挪到任何位置，行为自动正确。
切回 3D 后它又变回 16.0，说明这不是一次性开关，是每帧重算的几何关系。

十年树木则把"树长大撑破玻璃"当成**一个动作**：浇水同时关玻璃碰撞体 + 延迟隐藏网格 +
3D 桥生长，而不是三个各自独立的开关。生长动画只在玩家切回 3D 的那一帧开始，
玩家才看得见自己做了什么。

### 又修掉一个真 bug，这个卡住的是整关

`SafetyFootRing` 原来把"站得稳"和"有 3D 落点"用**同一个** `groundMask`（只有 Shared_Both）。
后果：玩家站在 2D 红毯上时（红毯在 Past2D_Only）被判成"脚下不稳"，
光圈永远暗红 —— 断桥关整关过不去，而这条路正是策划案 §2.2 设计的主线。

现在拆成两个层：

- `standMask`：**站住就算数**（Shared_Both + 2D 红毯 + 3D 枯木桥）
- `groundMask`：**真正的 3D 落点**（只有 Shared_Both）

相机测试里"站在坑上方的红毯上不能切回 3D"的行为**没有变**（因为没有 3D 落点，不是因为没有站稳）——
这两个规则以前被混成一个，现在分开了。

### 白膜的已知取舍

- **右断桥会挡 2D 镜头**：它在 +X，2D 相机从 +X 看过来，它就在玩家前面。
  策划案的解法是"三层构图 + RightWall_3D 剔除"，但断桥本身必须能站人，白膜阶段先这样。
- **两只巡卫只有占位方块**，没接 PatrolEnemy 的 AI（白膜只要求站位对）。
- **门外加了一块 9 m 过渡平台**：策划案没写门洞（Z=36，宽 6 m）到左断桥（X=-5）之间那 2 m，
  不加会掉进虚空。这块是我的补充，已在生成器里标注。
